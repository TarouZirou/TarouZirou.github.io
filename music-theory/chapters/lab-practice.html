計測と合成を一つの再現可能な作業にする

元の音素材、前処理、可視化、聴取、結論を同じフォルダの中に並べる。録音を眺めただけでは、「ここは高域が減った」が入力音・マイク・処理のどこで起きたか分からない。自分の正弦波と加算波を合成して正解の周波数を知ったうえで可視化し、その手順を録音へ移す。付属の音の実験室は、波形と窓付きFFTをすぐ確認する入口である。再解析には書き出した WAV の仕様も記録する。

例・手順

例　440と442 Hzの識別。 fs=48000f_s=48000 Hz で0.05秒観測すると標本数2400、DFT間隔20 Hz。ゼロ詰めでグラフ上の点を0.5 Hz刻みにしても、独立した周波数を観測したことにはならない。2秒観測なら窓幅は2秒、ビン間隔0.5 Hz。窓の主ローブ、S/N、トーンの安定性も比較に影響する。音を聴いてうなりを測る場合は1秒間の包絡の山を数え、スペクトルピークの差と照合する。目的に合う時間窓を後出しで選ばないように、比較する条件を先に定める。

標準ライブラリだけで一つの音を作る

以下は Python 3 の標準ライブラリだけで、1.6秒のうなりを PCM WAV に書く例。xx のピークは包絡が1以下で、二つの正弦の振幅係数の和 0.240.24 以下。dB SPLを保証する値ではないため、再生時は端末側の音量も下げる。最初と最後の20 msで経過時間に比例するフェードを掛ける。

import math
import struct
import wave

sample_rate = 48000
count = round(1.6 * sample_rate)
fade = round(0.020 * sample_rate)
pcm = bytearray()
for n in range(count):
    t = n / sample_rate
    env = min(1.0, n / fade, (count - 1 - n) / fade)
    x = 0.12 * env * (math.sin(math.tau * 440 * t)
                    + math.sin(math.tau * 442 * t))
    pcm.extend(struct.pack("<h", round(x * 32767)))

with wave.open("beats-2hz.wav", "wb") as output:
    output.setnchannels(1)
    output.setsampwidth(2)
    output.setframerate(sample_rate)
    output.writeframes(pcm)

最初に模範ファイルの長さを確認し、同じ出力を二回作って、内容が一致するか比較する。次に片方の442を440へ変更する。和が一定の倍振幅のサインになるため、フェード部分を除きうなりはない。差を7 Hzに変えると山の数が増える。0.1秒未満のファイルへ変えたときは、2 Hzの包絡の周期0.5秒の全体を、その窓内には収められない。位相を比較するときは初期位相と再生開始時刻を一致させる。

音源を公開用に検算する

公開するのは自作のソースとその音源、配信先のURL、用いた参考文献。教材に掲載されている録音はリンク先で聴く。第三者の音声を切り出して公開する場合は、対象とする配布条件を作品ごとに確認する。自作の譜例を公開するときも、音名表・楽譜・再生が一致するか、他の人が指定の小節を探せるかを検査する。

ここだけ押さえる

  • 0.05秒の観測ではDFTの間隔は20 Hz。440 Hz と 442 Hz は分けられない。
  • 比較の条件は、分析を始める前に決める。
  • 公開するのは、自作の素材と出典。
